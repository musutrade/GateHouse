# GateHouse Core 0.5.0

Core 0.5.0 已公开发布并独立验证，见[Core 回执](0.5.0-public-verification.md)和[与 Postgres 0.1.1 的固定产物验收](postgres-service-0.1.1-acceptance.md)。

这是含配置兼容性变更的 Core 版本。Postgres URL 隔离、外部健康检查、容器配方和旧配置迁移归 GateProbes；Core 只执行通用、必需且绑定摘要的 `service_checks`，保留服务生命周期和最终阻断决策。

## 升级要求

旧 v1 配方及 v2 `external_value_policy`（包括 `none`）会被拒绝。先安装并验证 GateProbes `postgres-service`，用其 `migrate --input <PATH> --output <NEW_PATH> --project <NAME>` 生成新文件，再审查并运行 Core `config check`、`doctor` 和 `verify`。迁移不覆盖原文件，保留步骤与独立质量配置，绑定已安装插件版本和摘要。插件独立发布；Core 发布成功不表示插件已发布。正式插件发布前应保留旧版本及原配置。

配置与消费者范围见 [EN 配置参考](../configuration.md)、[中文配置参考](../configuration.zh-CN.md)和[外置契约](../quality/postgres-externalization.md)。插件的 `pg_isready` 仅验证指定服务器是否就绪，不证明认证或 SQL 成功。

## 其他变更

- Git rename 的源和目标路径均用于组件选择，避免遗漏源组件验证。
- Rust 测量器使用固定、验证来源的 GateProbes 发行版；测量定义不变。
- 离线导入保留通用必需检查及原执行步骤；旧策略必须先迁移。

Engineering Policy、required gates、coverage/CRAP 阈值、baseline/debt/ratchet 和发布权威均保持不变。历史 0.4.9 标签、签名、资产和验证记录不变；0.4.9 不支持新协议。

## 安装与验证

发布完成后可执行 `cargo install harness-gate --version 0.5.0 --locked`，或从 `musutrade/GateHouse` 的 `v0.5.0` 下载对应平台的 Core。二进制安装使用该标签的 `install.sh --version v0.5.0`，按签名 inventory、SHA-256、Sigstore 和 GitHub provenance 验证。正式发布仍要求同提交 main CI 成功和完整签名发布流程；本说明不是交付回执。
