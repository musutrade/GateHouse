# GateHouse Core 0.7.0（待发布）

此版本候选基于 `08f980550960008eb7757df3c69459467aca74c0`。版本号和源码构建
不是发行证据；实际发行提交、摘要与 provenance 以正常发布工作流的清单为准。

## Linux 只读 runtime host

新增 `adapter runtime-probe-v2 --request ... --trusted-host ...`，使用独立的
受保护 host/config/expected 文件、固定 ELF 摘要、密封 fd 输入和有界进程监督。
实际请求必须与预期请求完全一致。Capabilities 仅声明 Inspect；Inspect 仅接受
Present 或 Unavailable，Remove 和 Absent 均拒绝。详见 [命令与信任边界](../runtime-probe-v2.md)。

这不是 Docker/Podman 引擎切换、租约迁移或容器生命周期交付。现有服务路径保留。
当前验收使用假 Unix socket，不证明真实 Docker 兼容性、daemon 身份、rootless、
重启检测或 OS 隔离。文件祖先目录依赖可信 euid/root；cwd 与可执行文件的祖先
并未获得额外所有权保护。协作式 intent 存储不证明断电或恶意回滚安全。

## 外部功能与兼容性

GitHub Check、GitHub Actions、hooks/canary 生命周期已由 GateProbes 独立交付；
Core 保留验证、质量决策及启动验证所需的 hook 执行入口。平台源码链接不再由
Core 生成，退役的 webhook 配置不再控制验证完成。

插件清单按 Core 版本精确匹配。onboarding-presets 1.0.0 不声明 0.7.0；
本次 Core CI 必须先固定已发布的 1.0.1 制品，不能以源码 checkout 替代。
1.0.1 对源码构建 0.7.0 的验收仅是候选证据。Core 发布之后，GateProbes 还需
使用下载的 0.7.0 二进制重验、更新固定摘要并交付其他兼容插件版本。
原有制品保持不变，历史 workload 证据保持原始 Core 身份。

native Docker adapter 仍未注册或发布；其发行在 Core 固定制品验收之后进行。
