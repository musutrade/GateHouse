# GateHouse Core 0.6.0

本版本将已经集成到 main 的插件 CLI 与输入/结果边界改造发行成固定制品。
发布前基线为 `120e73abd26e2ed0921deb6cb742d0ff5a3f776a`；实际发行提交、
制品 SHA、工作流身份与 provenance 以 v0.6.0 的发布清单为准。
此说明不是已经发布或验收通过的声明。

## 插件兼容性

已发行的 0.5.0 二进制不支持 `--plugin-store`、`--plugin-trusted-key` 和
`init --plugin`。以前以版本号 0.5.0 构建的 main 二进制支持这些功能，
但不能替代固定发行版。消费者必须同时固定发行来源、提交与制品摘要，
并实际验证所需 CLI 契约；不能只检查 `--version`。

0.6.0 提供已集成的显式插件存储、受信公钥与插件 preset 选择。
GateProbes workload 的发行归档由 GateProbes 发布工作流证明来源；
Core 安装清单仍由操作者审查并使用明确受信的 Ed25519 身份签名。
安装/升级插件不要求重新编译 Core。插件只提供命令或测量事实，
项目政策、requiredness、质量阈值、baseline/debt/ratchet、waiver 和最终结论仍归 Core。

## 输入、结果与执行

- 目录和暂存索引输入使用内容身份；快照支持的文件类型与目的地限制见
  `docs/input-snapshots.md`。
- `report-verify` 验证固定历史证据的完整性；历史有效不等于当前适用。
- 机器结果分别提供政策与 runtime 身份，不提供宿主隔离证明或自动复用许可。
- 外部结果消费者独立处理平台 Check 与传输失败，不再参与 Core 验证完成。
  迁移边界见 `docs/result-boundary.md`。
- Unix 正常退出也先清理进程组再 reap；取消在最终结果边界再次检查。
  进程组不是 OS sandbox，Windows 不宣称包含整个后代进程树。

## 采用与验证

使用现有 release.yml 的版本、main CI、签名及 provenance 验证流程。
不要覆盖 v0.5.0 或把未发行的本地构建重新标记为该旧版本。
在 GateProbes 更新到实际发行的 0.6.0 摘要之后，重新验证安装、预检、
固定包完整性和 workload 兼容性。原有工作负载证据保留其原提交和二进制身份，
不能在改版后静默换名。PR #127 不包含在本次发行中，也不合并。
